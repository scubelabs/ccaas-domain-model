# Vendor and Implementation Mapping Layer

The canonical model is vendor-neutral. Product-specific terminology belongs in mapping documents rather than in canonical definitions.

A mapping should document:
- canonical concept;
- vendor/platform concept;
- cardinality differences;
- lifecycle/state mapping;
- identifiers and correlation;
- fields that have no equivalent;
- semantic mismatches;
- lossiness of conversion.

Potential mappings can cover Kamailio/FreeSWITCH technical identifiers, carrier identifiers, CRM activity models and commercial CCaaS products. No compatibility claim should be made until a mapping is validated against authoritative documentation and/or implementation evidence.
